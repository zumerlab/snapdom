snapdom-vector

A snapdom plugin. Register it on a capture and that capture gains toVector(), toVectorSvg() and toVectorFigmaClipboard(). This page is the whole reference.

Getting started

Serve snapdom-vector.mjs from wherever you keep static assets and import it. It is one file with no dependencies of its own. snapdom itself is a peer dependency: it is not bundled in, so your page keeps one engine instead of two. Version 3 or later, because the engine walks the clone that snapdom's render hooks hand over and there is no second way to get one.

What the download contains: snapdom-vector.mjs, snapdom-vector.dev.mjs (the same code unminified), snapdom-vector-pdf.mjs for the PDF backend, and figma-plugin/.

import { snapdom } from '@zumer/snapdom'
import { vector } from './snapdom-vector.mjs'

const shot = await snapdom(document.querySelector('#plan-card'), {
  plugins: [vector()]
})

const svg = await shot.toVectorSvg()
document.body.insertAdjacentHTML('beforeend', svg)

Nothing runs on a server and nothing is uploaded. Everything happens in the page you are already looking at, which is the point: the component worth capturing is usually behind a login.

Use snapdom-vector.dev.mjs while you are debugging. It is the same code unminified, so a stack trace points at something readable.

Registering

Register it per capture. Registering it globally costs you something, so here are both forms and the reason to prefer the first:

// this capture only, and the one to use
await snapdom(el, { plugins: [vector(options?)] })

// every capture in the page
snapdom.plugins(vector(options?))

A plugin with render hooks suspends snapdom's burst optimisation on the captures it runs on, because burst answers with a memoized URL without re-entering the capture pipeline, and then there is no clone for this engine to read. Registered per capture, that cost lands on the captures that asked for it. Registered globally, it lands on all of them, including the toPng() in your hot path.

Then, on the capture:

shot.toVector(options?)               → Promise<SVDDocument>
shot.toVectorSvg(options?)            → Promise<string>
shot.toVectorFigmaClipboard(options?) → Promise<{html, plain, clipboardItem()}>

Options given to vector(…) are defaults for every export; the same names passed to an export call win for that call.

Both throw if the captured element has no layout box (an element with display: none has nothing to measure), and both throw if the capture carries no clone, which happens when burst: true was forced on the snapdom() call. Leave burst unset.

Everything about the capture stays on the snapdom() call. scale, dpr, backgroundColor, outerTransforms and the rest are read before the first hook runs, so this plugin could not override them if it wanted to. There is no second set of names for them here.

Options

OptionDefault
mode'design' What to do with a node that paints something the destination cannot describe and has text inside it. 'design' keeps the text editable and lets the effect go, saying so. 'replica' draws the node and pays with the text. The decision is made per node, not per document.
excludenone A selector, a predicate, or an array of either. Matching elements and their subtrees are skipped.
rasterFiltersfalse Rasterize, to a PNG, only the nodes whose filter an importer of Figma's class cannot execute: the colour functions of filter and backdrop-filter (saturate, brightness, contrast, grayscale, sepia, hue-rotate, invert), and inner shadows. Those nodes and no others. Off by default because it is a real loss: the subtree stops being editable everywhere, not only where it was going. Only toVectorSvg() consumes the result; the Figma and PDF backends emit the vector paint and say so.
debugPaintfalse Tint every node by stacking-context depth and give it a <title> naming its id, grade and paint order. The fastest way to see why a layer is where it is.
silentfalse Do not print the grouped diagnostics to the console. They are still in doc.diagnostics.
maxNodes20000 Ceiling on emitted nodes. Reaching it stops the walk and reports it.
maxDepth256Ceiling on tree depth.
maxDiagnosticsPerCode100 How many entries one code may contribute before it is summarised. A page with 4 000 identical warnings should not produce a 40 MB document.
fetchTimeout8000 Milliseconds, per asset.
maxAssetBytes8 MB Size past which an asset is reported. It is still embedded, because the document is self-contained by design, but you are told which one is heavy.

On toVectorSvg() only

OptionDefault
target'universal' Who the file is for. Not a preference: the destinations disagree on things one file cannot satisfy at once. See below.
exactShadowsby target true on 'universal': the exact filter chain, correct in a browser. false on 'figma': feDropShadow, which Figma can actually run, at the cost of folding spread into the blur.
textGradientMaskby target How gradient-filled text is written. false (universal) keeps it a real text layer with fill="url(#…)". true (figma) paints the gradient through a <mask> of the text, which arrives coloured in Figma and stops being a text layer there.

target: 'figma' is for the paste-an-SVG route. If the Figma plugin or the clipboard channel is available to you, neither of those trades is one you have to make: both carry the colours and the editable text.

The exports

shot.toVector() → the document

The SVD document: every node, its geometry, its paint, its grade, plus report and diagnostics. Validated against the schema before it is returned; an invalid document throws rather than shipping.

shot.toVectorSvg() → markup

A standalone SVG string. toVector() and then the SVG backend, in one call. If you already hold a document, use svdToSvg(doc) instead and do not walk the page twice.

shot.toVectorFigmaClipboard() → the paste envelope

Figma's own clipboard payload. A parallel backend off the same clone, not a consumer of the document. See below, and read it before you put it behind a button.

Module functions

import { svdToSvg, svdToFigma } from './snapdom-vector.mjs'
import { svdToPdf } from './snapdom-vector-pdf.mjs'

svdToSvg(doc, options?)   // → {svg, diagnostics}, also usable as the string
svdToFigma(doc)           // → the payload the Figma plugin consumes
await svdToPdf(doc, options?)  // → Uint8Array

All of them are pure and need no DOM: given a document they run in Node, which is how the test suite fuzzes them. That is the point of having a document in the middle at all.

The document

SVD: one versioned JSON document, one strict validator, and a backend per destination that is a pure function of it.

{
  schema: 'svd/1.0',
  generator: { name, version, engine },
  capture:  { url, selector, capturedAt, viewport, root, drift, conventions },
  assets:   { a_1: { kind: 'bitmap'|'vector'|'font', mime, w, h, data } },
  styles:   { text: { ts_0: { family, stack, size, weight, italic, … } } },
  root:     'n_0',
  nodes:    { n_0: { … } },
  diagnostics: [ … ],
  report:   { nodes, domElements, nodeRatio, drift, grades, coverage, … }
}

A node

{
  type: 'frame',            // frame | group | shape | text | image | vector
  name: '#plan-card',      // from tag, id, class or text; readable in a layer list
  frame: { x, y, w, h },   // relative to the emitted PARENT
  abs:   { x, y, w, h },   // relative to the capture root
  paint: { z, stackingContext },
  transform: null,         // { m: [a,b,c,d,e,f], decomposed: {…} }
  opacity: 1, blend: 'normal',
  clip: null, mask: null, radii: [ … ],
  fills: [], strokes: [], effects: [],
  text: null,              // only on type: 'text'
  control: null,           // only on a native form widget
  fidelity: { grade: 'E', notes: [] },
  source: { tag, path, css: {} },
  children: [ … ]
}

Invariants worth knowing

  • Units are CSS px, unrounded. Rounding is the emitter's business. Angles in degrees, clockwise. Y grows downwards.
  • Both coordinate systems are emitted. frame is relative to the emitted parent, abs to the capture root. abs survives any re-parenting and is what the test suite checks against the live DOM.
  • The hierarchy is DOM containment; paint order is paint.z, an integer computed from CSS 2.1 Appendix E. The backend sorts. A node is promoted out of its parent only when the order cannot be expressed by reordering siblings and the difference is geometrically observable. Every promotion is a B4.promoted diagnostic with from, to and a reason.
  • Colours are [r, g, b, a] floats 0..1 sRGB, with the original CSS kept alongside as srcCss. Out-of-gamut colours are mapped by reducing chroma, never by clipping channels.
  • blur is the CSS radius. SVG's sigma is half of it; that conversion is the emitter's, stated once.
  • Nothing is relative and nothing is external. Assets are embedded or referenced by a local id.
  • A document whose diagnostics do not explain its degradations is a bug, and the validator rejects it.

report

Measured on every capture, never promised in advance:

nodes / domElements / nodeRatio How much the pruning bought. A card is usually below 1.0: fewer nodes than elements.
drift {pairs, median, p95, max, worst}: the mounted clone's boxes against the live boxes they came from, in px. Every coordinate in the document is measured on that clone, so this is the error bar on all of it. Past 1px it is also a diagnostic.
gradesThe fidelity histogram: how many nodes at each grade.
coverage {pseudo, shadow, iconFont, artifact, synthetic}: nodes that a walk of the live DOM could not have produced at all.
vector / raster / textBlocks / assets / textStyles What the document is made of.
durationMs The mount, the walk, the collectors and the asset fetches. snapdom's own capture is the caller's to time, because the caller is the one who made it.

Fidelity grades

Every node carries one. Worst wins: a node with an approximated shadow and an exact fill is an A. Any grade other than E must be named by a diagnostic, and the validator enforces it.

Grade
E Exact. The destination can hold what the browser painted, unchanged.
A Approximated. A parameter was resampled or substituted: a conic gradient composed as wedges, a shadow spread folded into a blur, a colour-stop hint resampled to 16 stops.
C Composed. One CSS thing became several primitives: four border sides, an outline as a sibling, a decoration as its own path.
R Rasterized. Pixels, because there was no other honest answer: <canvas>, <video>, a filter chain nobody can execute.
RH Raster hybrid. The background is pixels and the text stays vector on top of it. The rule is that text does not go down with the effect if it can be avoided.
O Omitted. Nothing was drawn, and the reason is recorded. The most common one is the content a native form control paints for itself.

Diagnostics

Every approximation produces an entry in doc.diagnostics and a grade on the node it happened to. This half of the engine took as long to write as the drawing did, and it is the half you cannot replace: a capture that quietly lost a shadow looks fine until someone opens the file six weeks later.

{
  code: 'emit.svg.conic-fan',   // stable, greppable
  grade: 'A',                    // what it cost the node
  severity: 'warn',              // info | warn | error
  node: 'n_7',                   // which one, when it belongs to one
  message: 'conic-gradient has no SVG paint server; it is composed as …'
}

They are also printed to the console under [snapdom-vector], grouped by code with a count and up to three distinct messages. Four hundred identical warnings come out as one line and a count. silent: true turns the printing off and nothing else.

PrefixWhere it came from
capture.The clone and the mount: drift, restored root paint, CSS that could not be recovered.
B4.The paint tree: promotions, anonymous blocks, synthesized list markers, geometry taken from layout, form controls.
collect.The collectors, reading one element: a box, a text block, an image. What CSS said that could not be carried across.
compose.Cases where the contract says several primitives should be composed and this version emits one.
emit.svg.The SVG backend. What this file format could not hold, and what the destination it is written for will not run.
figma.The translation to the Figma payload. Kept apart from the engine's own list so the two never double-count.
h2d.The clipboard channel.
text.Typography that a destination is known to drop: tracking, features, small caps.
raster.What rasterFilters baked, and what it could not.

A diagnostic that says something was lost there rather than here keeps grade E. emit.svg.filter-not-imported is the common one: the file is exactly right in a browser and Figma will run only part of it. The node was not degraded; you were warned.

Text

One rule holds up the whole text path: the browser breaks the lines and the destination only draws them. No editor agrees with a browser about line breaking, vertical metrics or what line-height means, and asking one to re-wrap a paragraph produces bugs that look like the capture is wrong.

So a text node carries what was measured:

  • characters, with visual lines joined by U+2028, never \n, which would make a paragraph and trigger paragraph spacing in Figma.
  • lines[]: for each visual line its character range, its x, its painted width, its measured baseline, ascent and descent. Lines are grouped by baseline, never by top: a larger span shares a baseline but not a top.
  • pitch: the measured distance between consecutive baselines. Never the CSS line-height, which is a minimum and not an outcome.
  • runs[]: character ranges carrying a style id, a link, and dy, the measured offset of a raised or lowered run. Drop dy and H₂O renders as H2O.
  • line.frags, when something that is not a character (an inline image, a float) splits a line into separate painted stretches, and line.spans, the painted extent of each style stretch. It is the only place a backend can learn where the run carrying a wavy underline starts and stops.
  • line.hyphen: the glyph the browser painted at a hyphenation break, which the document does not contain. It is deliberately not in characters, because every offset indexes that string. Its advance is already inside the measured width.
  • sourceText: the pre-text-transform original, the same length as characters and indexed identically.

A text style is registered once in doc.styles.text and referenced by id, so a document with 200 paragraphs in three styles carries three.

The SVG backend

No foreignObject, anywhere. An SVG with a foreignObject in it is an HTML document wearing an SVG hat, and every vector tool opens it empty. Here a rectangle is a <rect> and a line of text is a <text>.

  • One <text> per positioned piece, meaning per visual line and per fragment within a line, each at its own measured baseline, whenever the block occupies more than one. A block that fits on one line stays a single element, which is the more editable object. See textPerLine.
  • The <text> carries the typography of its dominant run, and the <tspan>s carry only what differs, with explicit resets. Figma builds its text node from the outer element and does not look inside for the real values.
  • textLength is emitted only when a font binary travels with the file. Pinning a line to a width measured with your font, in a viewer that substituted a different one, does not degrade gracefully: it squeezes the glyphs. Without a binary the width is the viewer's, and emit.svg.text-length-viewer-width says so.
  • -webkit-text-stroke is a real stroke, and background-clip: text becomes the text's own fill rather than a glyph mask.
  • A <pattern> is emitted only when a layer genuinely tiles. Figma does not resolve a pattern reference and the node does not degrade; it disappears.
  • Native form controls are reconstructed at Chromium's measured proportions from the semantics the collector recorded (kind, state, accent colour), and every one says so (emit.svg.control-reconstructed). A reconstruction is not a capture. The Figma and PDF backends do not draw them.

The file is self-describing: the approximations are written into an XML comment under the <svg> tag, so a file that travels without its report cannot exist.

Figma: the plugin

The included plugin turns a document into real layers through the Plugin API: frames, editable text, gradients, radii, shadows, per-side borders, images. It is deliberately dumb: svdToFigma(doc) does the translating where it can be tested in Node, and the plugin builds what it is handed.

Loading it

  1. Figma → Plugins → Development → Import plugin from manifest…
  2. Pick manifest.json from the plugin folder.
  3. Run it from Plugins → Development → SnapDOM Vector.

Using it

  1. Drop a .svd file on the window, or paste its JSON into the box. What that file contains is svdToFigma(doc), not the raw document. The plugin never sees an SVD, so that there is exactly one place where SVD becomes Figma vocabulary and it is testable in Node.
  2. Read the preflight. It is blocking on purpose: before a single node exists you see every font that is missing or will be substituted, with the number of text blocks and characters riding on it, plus the layer count, and every degradation the engine declared, grouped by code.
  3. Decide what to do with each font: accept the substitution, map it to something installed, or use the pre-baked outlines or bitmap if the document carries them.
  4. Create layers. The result is selected and zoomed to, and the final screen lists what was approximated during the build.

Nothing leaves the machine. The manifest declares networkAccess: {allowedDomains: ["none"]}, so the plugin cannot make a request even if it wanted to.

It validates the payload version and rejects without repairing. A document written by a different version of the engine is a hard stop naming both versions. Repairing it would ship the bug instead of reporting it.

Why some options are greyed out. Outlining and rasterizing happen in the browser, where the real font is loaded: the Plugin API has no outlineText() and the sandbox cannot rasterize, so the plugin can only use an outline or bitmap the capture already contains. When it does not carry one, the option is disabled and says why.

Do not upload a captured font binary to your Figma account. Captured binaries are subsetted to the glyphs the page used. Uploading one would name it "Inter" while carrying a fraction of Inter, and every other file in your account would get silent tofu. The preflight shows the correct internal name and the original URL instead.

Figma: the paste channel

toVectorFigmaClipboard() writes Figma's own clipboard payload, so ⌘V works with nothing installed. It is a different kind of export from the other two and you should read this before putting it behind a button.

  • The format is theirs: proprietary, undocumented, reverse-engineered, and already at version 2. Figma can change it in any release, with no negotiation and no error. The only symptom is a paste that does nothing.
  • What it buys is what the SVG importer cannot do at all: letter-spacing survives. We measured it: a 376.8px line of text arrives at 449px through the SVG route, +50px of that from ignored tracking.
  • Nodes whose paint the channel cannot spell are drawn by the SVD backend and carried as an image, unless they have text inside them, in which case mode decides. vectorFallback: false turns the drawing off, and still reports what it would have drawn.
  • Effects that read what is underneath a node (mix-blend-mode, backdrop-filter) arrive unblended. Figma's own extension loses them too.

toVectorSvg() is not going anywhere, and it is the one that opens in tools nobody owns.

PDF

import { svdToPdf } from './snapdom-vector-pdf.mjs'

const bytes = await svdToPdf(doc, { compress: true })

It is a separate file because a capture that never asks for a PDF should not carry one: the main module does not import it, so nothing about PDF reaches your bundle unless you write that import.

A vector PDF from the same document: geometry and real text, not a picture of a page. A box is a path, a gradient is a shading, and a line of text is a Tj at its measured baseline.

This is not snapdom-pdf running underneath. Neither plugin imports the other. What they have in common is one internal module, the byte-level writer that counts objects, builds the xref table and deflates streams, and each build inlines its own copy of it. Everything above that is separate: snapdom-pdf lays an invisible text layer over a raster, this walks the SVD and draws it, and buying one gives you no part of the other. Both builds fail if the bundle so much as names the other product.

It has the smallest primitive set of the three backends. PDF has no blur, so every blurred shadow is shadowLayers concentric copies, and it has no colour matrix at all. There are no font binaries in an SVD, so the glyphs come from the base-14 fonts and the diagnostics name every substitution. It paginates nothing on its own; pages takes finished page geometry from a caller that owns the pagination.

The diagnostics ride on the returned array and are written into the file as an uncompressed object off the catalog, so strings out.pdf finds them. An approximation that only reaches a stream nobody opens is a silent degradation.

snapdom-pdf is pixel-exact and zooms like a photograph. This one has no resolution and re-draws the page, which means it can substitute a font on you. Pick by which failure you can live with.

What reaches the document, and what does not

The engine walks the clone snapdom already resolved, which is why membership in the tree is not an argument here. In:

  • Pseudo-elements (::before, ::after, ::first-letter) as real nodes with real boxes, with counters and quotes resolved.
  • Shadow DOM, flattened, so slotted content appears once, at the slot.
  • Icon fonts resolved by ligature, and inline <svg> carried as vector with its element ids namespaced per instance.
  • Images from currentSrc, so srcset resolves to what was actually shown, with object-fit and object-position expressed as a crop plus a matrix. An SVG source is inlined as vector, not rasterized.
  • Scroll offsets, applied, and overflow clipping as a real clip.
  • Native form controls, described as controls: kind, state, accent, track and thumb colours.
  • <canvas> and <video>, as bitmaps. A tainted canvas is omitted with a reason rather than throwing.
  • In-flight animations, at the values of the frame that was captured.

Out:

  • Anything exclude named, and anything snapdom itself excludes.
  • display: none, visibility: hidden, and content clipped away by an overflow ancestor.
  • The value inside a native control. The text in an <input>, the chosen <option> of a <select> and a placeholder are painted by the browser itself and no CSS property describes them; they are graded O and named. The widget's frame, border and background are drawn.
  • Cross-origin iframes. The frame is a placeholder with its URL in the metadata.
  • Closed shadow roots, which are unreadable by anyone.

Recipes

A capture, and its report, before you use it

const shot = await snapdom(el, { plugins: [vector({ silent: true })] })
const doc = await shot.toVector()

if (doc.report.drift.median > 1) warnTheUser(doc.report.drift)
const lossy = doc.diagnostics.filter(d => d.grade && d.grade !== 'E')
console.table(lossy.map(d => ({ code: d.code, node: d.node, why: d.message })))

One capture, every format

const shot = await snapdom(el, { plugins: [vector()] })

const doc = await shot.toVector()
const svg = svdToSvg(doc).svg          // not toVectorSvg(), which walks the page again
const fig = svdToFigma(doc)
const pdf = await svdToPdf(doc)
const png = await shot.toPng()

Hand a .svd to the Figma plugin

const doc = await shot.toVector()
const blob = new Blob([JSON.stringify(svdToFigma(doc))], { type: 'application/json' })
const a = Object.assign(document.createElement('a'), {
  href: URL.createObjectURL(blob), download: 'capture.svd'
})
a.click()

See why a layer is where it is

const svg = await shot.toVectorSvg({ debugPaint: true })

Every node is tinted by stacking-context depth and titled with its id, its grade and its paint order. Hovering tells you which node you are looking at, which is the question you actually have.

Buy the effect and pay with the text

await snapdom(el, { plugins: [vector({ mode: 'replica' })] })

Limits

Written down because you will meet them, and meeting them here is better than meeting them in front of a client.

  • Chromium. Everything is measured there and the pixel baselines were recorded there. Other engines are not tested, and claiming them would be the same silence this engine is built against.
  • No font binary travels. The document names the family and the face; it does not embed the file. Subsetted binaries are the only ones a capture has, and shipping those into someone's font list poisons it. So a viewer without your font substitutes one, and textLength is withheld rather than squeezing glyphs into a width they were never going to produce.
  • A system font keyword is not a font name. Text painted by -apple-system or system-ui cannot tell any destination which face to load.
  • Auto Layout is not inferred. Everything lands positioned. A frame you can move is not a frame that reflows, and guessing wrong at the layout is worse than not guessing.
  • Masks are not applied by the current Figma plugin: the masked node is built as an ordinary layer, and the plugin says so.
  • The value inside a native form control is not captured (see above). The widget is.
  • backdrop-filter does not survive. Frosted glass is a blur of whatever happens to sit behind the panel, and neither SVG nor Figma has a way to say that about an arbitrary backdrop. The panel arrives as a flat colour, the node is graded and named, and rasterFilters does not rescue this one: it bakes the node's own filter, not the backdrop it was reading.
  • A conic gradient becomes 128 flat wedges plus a small disc capping the apex the wedges cannot cover. SVG has no conic paint server.
  • Shadow spread is approximate. feMorphology's kernel is rectangular, so the spread corners are; with target: 'figma' the spread is folded into the blur, loudly.
  • 3D transforms are flattened to their 2D projection, with a diagnostic. Nothing projective survives.
  • Figma's SVG importer drops letter-spacing, ignores font stacks and does not resolve pattern fills. None of that is fixable from this side; all of it is measured, declared, and avoided entirely by the plugin and the clipboard routes.
  • Figma has no colour-matrix effect, so filter: saturate(…) and its relatives have no equivalent there at all. They are named, with the CSS verbatim, rather than dropped quietly. Or baked, if you ask for rasterFilters.
  • The capture is one subtree, one viewport, one moment. No page-wide capture, no responsive variants, no component variants inferred from a static picture.
