Capture stages

A capture is a chain: the live DOM is walked, a clone freezes that instant, and a render turns the clone into pixels. Not every consumer needs the whole chain, and the plugin is the one that knows. So it declares it:

{ name: 'my-plugin', needs: 'live' }   // reads the page, no clone, no pixels
{ name: 'my-plugin', needs: 'clone' }  // annotates the frozen tree, no pixels
{ name: 'my-plugin' }                  // default: the whole pipeline, as always

The stage of a capture is the deepest stage its plugins declare, so one undeclared plugin keeps everything. A capture with no plugins behaves exactly as it always did.

What the numbers say

Stopping before the render saves almost nothing: serialization is a few percent of a capture. Stopping before the clone is the cut that matters, and it is exactly the one a plugin can know about and a caller cannot.

What was never produced is never faked

Ask a shallow capture for pixels and it throws, naming the plugin that lowered the stage. Re-capturing on demand would hand back an image of a different instant, and the caller would have no way to tell.
