A live element, as text

Type in the card. The right side is the same element redrawn as ASCII art on every change, through the stream plugin.

TL;DR

Two plugins, chained. stream() keeps a canvas in step with the card and repaints only the boxes that changed. asciiFromCanvas(), the function behind the ascii-export plugin, turns each frame into characters. No capture result in between: the canvas goes straight from one to the other.

What you're looking at

The left card is editable HTML on a white background with solid-colored boxes, the shape the stream plugin patches best. The right pane is a <pre>. On every frame the plugin hands over its canvas, the text is recomputed and replaced. Pick a character set, change the width, or switch to color to see each character carry the pixel it came from.

How it works

  1. stream() watches the card

    The first frame is a full SnapDOM capture. After that, a mutation or a keystroke is traced to the nearest box with a solid background, and only that subtree is captured and drawn into its rectangle.

  2. onFrame hands over the canvas

    Each repaint calls onFrame(frame) with frame.canvas and the list of changed rects. The demo ignores the rects and converts the whole canvas; it is 90 columns wide, so that costs under a millisecond.

  3. asciiFromCanvas() does the pixel work

    It downsamples the canvas to one pixel per character, maps luminance to the charset and returns a string, or colored HTML when format: 'html'. It is the same code the toAscii() export uses, exported on its own so it can run on any drawable.

  4. The <pre> is replaced

    textContent for plain text, innerHTML for the colored version. Nothing else on the page is touched.

Copy-paste example

import { stream } from '@zumer/snapdom-plugins/stream'
import { asciiFromCanvas } from '@zumer/snapdom-plugins/ascii-export'

const out = document.querySelector('pre')
const live = stream(document.querySelector('#card'), {
  onFrame(frame) {
    out.textContent = asciiFromCanvas(frame.canvas, { width: 90 })
  }
})
await live.ready
// later: live.stop()

The same pattern works for any pixel-level plugin: color-tint or filter on a frame, a video element instead of a stream, or a canvas you drew yourself.

Limits and things to watch

Patches need a solid background somewhere above the change; on a gradient card every frame is a full capture. Width above 140 columns makes the conversion visible in the frame budget on slow machines. Color mode produces one <span> per character, so keep it under 100 columns.
