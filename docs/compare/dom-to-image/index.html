A quick overview

dom-to-image clones a node, inlines CSS and assets, and wraps it in a <foreignObject> for the browser to render. Its API returns image data URLs or a PNG Blob. Check its repository for current releases and supported browsers.

SnapDOM is a from-scratch implementation of the same idea, with active development and a plugin system on top. The capture pipeline is exposed through lifecycle hooks (beforeClone, afterClone, beforeRender, afterRender, beforeExport, afterExport) so you can alter capture state, observe exports, and add custom exporters without forking the library.

When to use which

Choose SnapDOM when…

  • You need active maintenance and bug fixes.
  • Your UI depends on modern CSS features (variables, pseudo-elements, line-clamp).
  • You use Web Components or Shadow DOM.
  • You want to add custom export formats or transformations through plugins.
  • You need first-class TypeScript types out of the box.

Check before migrating…

  • Compare captures of your layouts in each browser you support.
  • Test web fonts, open Shadow DOM, CSS counters and line-clamp with your content.
  • CommonJS-era packaging and no bundled TypeScript types.

Same task, side by side

Capturing #card as a PNG and inserting the resulting image into the page:

dom-to-image

import domtoimage from 'dom-to-image';

const dataUrl = await domtoimage.toPng(document.querySelector('#card'));
const img = new Image();
img.src = dataUrl;
document.body.appendChild(img);

SnapDOM

import { snapdom } from '@zumer/snapdom';

const img = await snapdom.toPng(document.querySelector('#card'));
document.body.appendChild(img);

SnapDOM returns the HTMLImageElement directly so you can drop the data-URL plumbing.

Frequently asked questions

Is dom-to-image still maintained?

Check the dom-to-image repository for its release history and open issues. Before migrating, compare your captured output and account for the return-type and option differences shown above.

How do I migrate from dom-to-image to SnapDOM?

Import @zumer/snapdom and start with snapdom.toPng(element). Read .src on the returned image if the caller expects a PNG data URL. Rename bgcolor to backgroundColor, invert inclusion predicates for exclude, and review output sizing.

Does SnapDOM support custom fonts?

Yes. In v3, embedFonts: 'auto' embeds used web fonts by default. Font files must be accessible; localFonts and excludeFonts give additional control.

What about Shadow DOM?

Open Shadow DOM trees are walked and cloned by SnapDOM, so Web Components capture correctly. dom-to-image does not natively support this.
