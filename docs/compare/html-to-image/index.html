A quick overview

html-to-image is a fork of dom-to-image with TypeScript support. Its image helpers return data URLs; it also provides Canvas and Blob exports.

SnapDOM exposes capture and export lifecycle hooks. Official plugins add portable HTML, structured context and maps, PDF images, GIF and video alongside filters, timestamps and text transformations. These plugins are separate from the core image and canvas exporters.

When to use which

Choose SnapDOM when…

  • You use Web Components or Shadow DOM heavily.
  • You need CSS counters or line-clamp ellipsis in the captured output.
  • You want to add filters, watermarks, ASCII or PDF export without forking the library.
  • You need fine-grained font control (embedFonts, localFonts, excludeFonts).

Check before migrating…

  • SnapDOM plugins extend the capture lifecycle; existing html-to-image post-processing needs adapting.
  • Compare open Shadow DOM, CSS counters and line-clamp on the components you ship.
  • html-to-image has font embedding controls and canvas-based encoding; compare option semantics before mapping them.

Same task, side by side

Capturing #card as a PNG and inserting the resulting image into the page:

html-to-image

import { toPng } from 'html-to-image';

const dataUrl = await toPng(document.querySelector('#card'));
const img = new Image();
img.src = dataUrl;
document.body.appendChild(img);

SnapDOM

import { snapdom } from '@zumer/snapdom';

const img = await snapdom.toPng(document.querySelector('#card'));
document.body.appendChild(img);

Frequently asked questions

What's actually different between html-to-image and SnapDOM?

Both clone the DOM and render via foreignObject. SnapDOM adds capture lifecycle hooks, automatic reuse for eligible repeat captures, and official plugins for HTML, structured context and maps, PDF images, GIF and video. Compare the return types and options in the migration table.

Does SnapDOM render web fonts better than html-to-image?

Both libraries can embed @font-face declarations. SnapDOM v3.x.x defaults to embedFonts: 'auto' for used web fonts and also supports localFonts and excludeFonts. Check the exported text with your actual font files and browser.

Can I add a watermark or filter without forking the library?

Yes — that's exactly what the SnapDOM plugin system is for. Use the colorTint, filter or timestampOverlay plugins, or write your own with two callbacks (afterClone / beforeExport). Browse the plugins page for the full list.

How do I export to PDF?

Use the MIT pdf plugin. Its toPdf() method returns a PDF Blob with selectable text, pagination and links. The updated package is prepared locally; see the PDF reference for installation and examples.
