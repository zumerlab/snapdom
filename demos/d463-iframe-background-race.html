#463 — CSS backgrounds intermittently dropped with same-origin iframes

3 background-image squares (from a stylesheet rule, top-left corner of the stage) sit as direct siblings of 6 same-origin iframes and some filler text (their content isn't the point — they're just there to trigger nested captures that race with the parent's own clone; each does a real fetch+decode so several nested captures actually overlap in time). Nested iframe captures used to reassign the shared cache.session.nodeMap concurrently; nothing enforced which one "won" it, so the parent's background pass could read an orphaned empty map and silently skip every background. Runs below capture the same stage 6 times in a row — before the fix this failed every run (0/3 backgrounds); after the fix all 6 runs show 3/3.
