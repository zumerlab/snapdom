#486 — capturing an animated canvas

A canvas is captured by reading it back with toDataURL, so snapDOM can only see what has already been drawn: firing the capture in the same tick that starts an animation (the reported case loaded a Lottie file and captured immediately) serializes an empty canvas. Both canvases below draw a deterministic first frame at load, so the capture must match the live pixels whether the animation is playing or not. Capture too early reproduces the reported mistake on purpose, and { debug: true } now warns about it.
